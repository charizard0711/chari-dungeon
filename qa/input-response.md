# 方向キーの取りこぼし修正（2026-09-11）

## 原因

GameScene.handleMoveKeys が busy 中に即 return し、キーの押下イベントを保持せず、行動可能なフレームの isDown だけを見ていた。敵アニメーション中に押して離すと、キー入力が失われる。同じキーを押し直しても以前の長押し判定が残る場合があった。

1・2階の新しいボスの歩行は最低280ms、爪480ms、ブレス640msを固定で待っていたため、この取りこぼしが起こる時間が増えた。

## 変更

- keydown で次の1行動を保持。新しく押した方向を優先し、大量の自動行動は予約しない。
- keyup と長押し解除は busy 中にも反映。OSのキーリピートは追加予約しない。
- メニュー・ゲーム終了・フォーカス喪失・階層切替で古い入力を破棄。シーン終了時にイベントを解除する。
- 描画済みボスの歩行は通常116ms、加速時は最低80ms。爪は通常280ms、ブレス400msで長押し加速にも対応する。
- 攻撃4コマと3コマ目のダメージ判定を維持する。

## 検証

`qa/input-response.html` は実際のゲームを起動し、下キーを20ms押したあと、移動処理中の125ms時点で次のキーを20ms押す。

| 条件 | 押下 | 処理中の押下 | 実際の行動 |
| --- | --- | --- | --- |
| 修正前・1階・下→左 | 2 | 1 | 1（FAIL） |
| 修正後・1階・下→左 | 2 | 1 | 2（PASS） |
| 修正後・2階・下→左 | 2 | 1 | 2（PASS） |
| 修正後・2階・下→下 | 2 | 1 | 2（PASS） |

全成功例で最終座標も一致し、処理中=false、予約なしで停止した。修正前の再現時にも約180FPS以上あり、入力待ちが主因と確認できた。

- `node scripts/qa-movement-input.mjs`: 実際のシーンのメソッドで、短押し・押し直し・方向変更・長押し・解除・入力破棄・移動と攻撃の時間を検証。
- `node scripts/qa-monster-animation.mjs`: 4方向・攻撃コマ・透過シートを検証。
- `npm run build`: TypeScript と本番ビルドが成功。
